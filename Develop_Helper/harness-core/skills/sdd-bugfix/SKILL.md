# 项目问题修复

接收已定位的项目路径、问题描述和已有授权。只处理当前缺陷，不重走项目创建和完整设计流程。按 [错误与经验闭环](../../protocols/experience-loop.md)（路径：`<harness_root>/harness-core/protocols/experience-loop.md`）执行，由修复者返回结论、Tester 复验、主智能体作为编排器记录经验。

## 定位

1. 确定触发操作、实际结果和预期结果。优先采用用户已说明的要求或 PRD 中的 AC；仅在预期仍有歧义时补问，不对已确认行为再次设门禁。
2. 按问题定位相关功能、接口和代码，只读 `docs/PRD.md`、`docs/tech-spec.md` 的对应章节；有任务时查看相应 AC 与状态，有原型时才对照相关页面。
3. 编排器按关键词定向检索项目经验（路径：`<active_project_path>/.sdd/experience.md`），向修复者传递命中标题；已提供时直接复用，没有记录不阻塞。同类复发核对旧条目的适用条件和执行情况。规范以项目 `.sdd/project.json` 为准，`null` 不加载规范集。
4. 复现并说明直接原因和影响范围。接口问题对照技术方案第二层，数据、算法和异常分别对照相关章节；缺失信息与已验证结论分开记录。

## 修复与验证

在当前授权范围内做必要修改，保留其他人的改动。按真实技术栈执行与缺陷相关的检查；能覆盖问题复发的测试才补充，不为文案小改强造测试。

预期行为、AC 或接口约定需要改变时，交回主智能体更新对应设计并确认；不能通过改写验收让缺陷通过。任务中的状态由编排器维护，修复者返回结果和证据。

确认原问题消失并检查受影响的相关行为。没有实际运行的验证说明原因；权限不足或真实服务未验证时保留限制，不宣称全部通过。

## 交付

返回根因与证据、修改文件、适用条件、预防办法、验证结果、遗留问题及经验建议；推测单列。编排器安排 Tester 复验，复验前仅保存错误事实。任务内记录到 tasks 的 notes（路径：`<active_project_path>/.sdd/tasks.json`）；无任务时记录到工作日志（路径：`<active_project_path>/.sdd/work-log.md`），不补造任务。复杂问题长证据才保存单份 Bugfix 报告（路径：`<active_project_path>/.sdd/bug_fix/<实际报告名>.md`，交付时给出实际绝对路径）。

复验后由编排器判断、去重并维护项目经验（路径：`<active_project_path>/.sdd/experience.md`），在原错误记录注明条目或不新增原因；修复者与 Tester 不直接维护经验库。未完成必要复验或根因未证实时不包装成已验证经验。全局候选经用户授权再维护；任何记录均不含密钥或敏感原始数据。
