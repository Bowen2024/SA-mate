# 删除或重置项目

先明确目标项目和用户想重新开始的范围。沿用已确定范围；“重新测试”不自动等于删除代码、数据库或整个项目。

| 意图 | 操作 |
|---|---|
| 只清测试数据 | 根据当前项目的存储配置和测试脚本定向确定数据范围，使用已有清理方式；没有安全清理方法时先给出具体文件/记录范围。保留代码、设计、任务与登记，不套用其他项目的数据路径。 |
| 重跑某阶段 | 保留上游已确认产物，将本次要重跑的输出和证据归档；追加本轮任务或注明旧结果失效，不批量将所有历史任务改为 pending。受影响的下游结果需复验。 |
| 完全重新创建/移除项目 | 停止该项目服务，将整个项目可恢复地移到框架外备份，移除注册记录并清空对应活动项目。释放原 ID 和路径；保留通用 Skills、规范与其他项目。 |

仅在范围不明确时询问。用户明确“清空整个项目从创建开始”已经授权完整移除，不再次要求相同确认。永久删除备份、删除远程仓库、清理其他项目均不包含在该授权内。

## 完整移除

1. 直接读取注册表（路径：`<harness_root>/project-registry.json`）和目标身份（路径：`<active_project_path>/.sdd/project.json`），核对 ID、实际绝对路径且属于 Projects_Repo 直接子目录。记录异常先核对，不用目录名称猜测身份。
2. 停止该项目仍运行的开发/验收任务，避免继续写入。按项目实际端口、进程 cwd 和启动命令定位服务；只停止已确认属于该项目的服务，不按 python/node 名称批量杀进程。保留用户终端及其他项目服务。
3. 告知框架外备份目录，执行 [项目脚本](../../../../scripts/sdd_project.py)：

   ```bash
   python3 scripts/sdd_project.py remove "<project-id>" --backup-dir "<框架外、尚不存在的备份绝对路径>"
   ```

   脚本将目录及原注册表快照放入备份，移除目标登记；仅当被移除项目是活动项目时设 null，不任意激活其他项目。脚本不终止服务、不访问远程仓库，也不永久销毁备份。使用同一文件系统中的普通目录；跨文件系统移动拒绝并保留原项目。
4. 核对原路径已释放、目标记录已移除、原服务端口无旧项目监听，其他登记未变。失败时报告已完成步骤和可恢复位置，不宣称重置成功。
5. 返回删除/修改的路径及备份位置。只有用户同时要求重新创建时才进入创建分支；“我自己重跑”则到此结束，不自动创建。

恢复时先核对 ID 与目录未被新项目占用，再将备份目录迁回并仅恢复该项目的登记；不得用旧注册表覆盖期间新增的其他项目。
