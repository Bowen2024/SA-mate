# Codex 子智能体协议

Codex 通过 `.codex/agents/` 的薄适配器引用 `harness-core/agents/`。Planner、Developer、Tester 和 Solution Designer 的职责只在核心角色文件维护。

## 调度

编排器传入目标项目绝对路径、当前任务或设计目标、必要输入章节、允许写入范围和输出要求。每次只读取当前角色和任务需要的内容。有可用的子智能体调度能力时，实际派发对应角色；读取角色文件本身不算启动子智能体。

编排器维护 `.sdd/tasks.json` 的任务状态，汇总 PASS／FAIL／BLOCKED 并执行确认与重试规则。Planner 返回任务草案；Developer 返回代码变更与验证结果；Tester 独立验证并返回证据，长证据才另写报告，不直接修改任务状态。

流程细节见 [开发循环](development-loop.md)。

## 设计与规划必须实际派发

- PRD 确认、首次进入七层方案：派 `solution-designer`；技术方案和必要界面确认、首次生成计划：派 `planner`。主智能体只组装输入、转达用户决定和核对结果，不用读取角色文件替代调用。
- 调用当前平台实际暴露的子智能体创建工具，指定角色或在任务中明确角色文件绝对路径；通用子智能体也可承接角色，不要求工具恰好叫某个固定名称。调用返回真实实例 ID 后才记录已启动，不创建用户侧独立聊天任务冒充子智能体。
- 各阶段记录“角色、实例 ID、输入/输出路径、执行结果”于当前编排上下文；压缩或换会话时从真实调用记录恢复，无法核实则说明未知，不能编造已派发。
- Solution Designer 返回方案草案/待决项，主智能体与用户对齐；Planner 返回完整 tasks 与门禁、依赖、并行及阻塞摘要。未收到所需产物，不越级开发。已有有效计划只做受影响调整，不重复启动首次规划。
- 当前任务若是维护框架本身，角色名出现在待编辑文档里不等于要启动对应项目设计流程。

## 运行与结果回收

- 派发成功后记录真实子智能体标识、对应角色/任务和工作区，保留在编排上下文，必要时写入当前任务 notes；不另建状态文件，不使用编造的标识等待。
- 按开发循环先派完当前名额内不冲突的就绪任务，再等待任一运行任务返回。使用当前平台实际支持的等待/状态工具；不支持等待任一时，做有界状态查询并及时处理已完成者，不在一个无输出实例上无限等待。
- 工具调用结束或界面显示 Stopped 都不等于业务任务完成。核对实际实例状态、终止原因及最终返回；已有有效成果交后续验收，只有局部成果则记录未完成部分。状态不明时先查询，不重复派发。
- 确认旧实例已终止且需要恢复时，沿用原任务与成果，重新派发剩余工作；不能让两个实例同时写同一任务。用户主动暂停/取消时不自动恢复；环境或权限缺失按 BLOCKED 处理，代码 FAIL 按原返工计数处理，不因实例停止就判 PASS、算代码失败或清零重试。
- 已终止且无可用结果的实例不继续等待；记录具体原因与恢复条件。名额释放方式以平台能力为准，不中断无关运行任务腾位置。

## 能力不足时

只有当前工具列表确实没有调度能力，或实际调用返回明确的不可用错误时才降级；先说明具体限制。名额已满时等待现有任务释放，不等同于平台不支持，也不静默转由主会话重复执行。

确认当前环境无法直接启动子智能体时：

1. 主会话明确当前承担的角色，读取该角色核心文件。
2. 完成该角色的限定任务，再切换下一角色。
3. 保持设计、实现、验证和状态维护的职责边界。
4. 如由同一主会话验证自身实现，如实说明，不能声称已有独立子智能体复核。

使用当前环境真实可用的调度工具；配置文件存在本身不证明运行时已支持对应能力。
