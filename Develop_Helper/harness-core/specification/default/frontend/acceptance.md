# 前端验收（default）

仅项目明确选择 `default` 且任务引用本件时使用，保留 React / TypeScript 工程验收要求。
任务派发、返工和用户确认遵守开发循环协议，不在规范中另设开发节奏。

## 输入与范围

- 从 `.sdd/tasks.json` 取得本任务及 `context_files`，仅阅读相应章节。
- 用户结果与 AC 来自 `docs/PRD.md`；接口和响应来自 `docs/tech-spec.md` §二，运行配置来自 §七。
- 按已确认风格文档的相关章节核对视觉取值；有原型时对照页面，无原型时按风格文档、PRD 界面约定与任务 AC 验证。两份设计冲突时交回设计对齐。
- 页面实现需要新增用户结果或改变范围时交回编排器，不自行改 AC、方案或任务状态。
- 状态统一由编排器写入 `.sdd/tasks.json`，不维护另一套页面计划或全局进度文档。

## 实现顺序参考

单个页面可按路由与访问控制 → 页面骨架 → API Service → Hooks / 按需共享 Context → 组件推进。
仅任务明确需要 Mock 时使用 Mock；不强制先做完全部页面再接后端，也不自动推进下一任务。

## 验收清单

对当前改动适用的条目进行检查；纯文字小改以差异和呈现核对为主，不强造测试。
端口与代理取值见 `shared/env-policy.md`。

- 项目配置 `type-check`、`lint`、`build` 脚本，并按改动影响范围通过；类型检查使用与项目 tsconfig 匹配的 `tsc`，lint 包含 React Hooks 规则，build 使用 Vite 的 React 配置。
- JSX 文件使用 `.tsx`，入口通过 `createRoot` 挂载；Vite 已启用 `@vitejs/plugin-react`。Hooks 调用位置合法，effect 的订阅等资源有必要清理。
- 需要运行页面时开发服务器可启动（Agent 端口 5199 / 用户验收端口 5175）。
- 涉及路由时 React Router 跳转正常，受保护页面按认证状态展示、等待或跳转；登录状态变化能反映到界面。
- Mock 数据如有，集中在 `src/mocks/`，格式对齐技术方案 §二，并使用可见的 Mock 标识。
- 配色、间距、圆角、字号与 `docs/ui-style.md` 的已确认取值相符；布局按实际页面设计核对，未提供原型不构成统一阻塞。
- `baseURL` 来自环境变量，无硬编码后端地址；Vite 配置 `/api` 及实际需要的 `/ws` 代理。
- 组件内无直接 axios 调用，401 在拦截器统一处理。
- 交互组件覆盖默认态、`:hover`、`:active`、`:focus-visible`、`:disabled`，见 `style.md`。
- 多栏页面固定视口高度，各栏 `min-height: 0` 并独立滚动；侧栏列表顶部对齐，见 `style.md`。
- AC 要求真实闭环时，通过实际页面动作验证真实请求与用户结果；不能用静态检查或构建成功替代。
- Mock 验证与真实联调分开报告；无法完成必要真实验证时说明原因，不降低 AC 后判 PASS。

## 交回编排器

返回逐 AC 的 PASS / FAIL / BLOCKED、实际结果和必要证据；失败提供具体复现步骤。
不改业务代码以制造通过条件，不自行改任务状态或安排后续开发；较长证据才另存任务报告。
