### 原样继承

1. 编排器统一维护执行状态，Developer 和 Tester 只返回结果与证据，不直接修改权威状态。
2. Developer 一次只实施一个已授权任务，遵守明确项目、上下文、写入范围和验收条件，不自行推进下一任务。
3. Tester 使用同一任务和 AC 独立判定 PASS、FAIL 或 BLOCKED，不修改业务实现、需求、方案或任务状态。
4. Planner、Developer、Tester 和 Solution Designer 的职责保留一个核心来源；平台入口只引用，不复制第二套角色规则。
5. 读取角色文件不等于已启动角色；必须记录真实运行实例、输入、输出、终止原因和结果。
6. 并行任务必须具有不冲突的写入范围；共享配置、锁文件、类型和路由等指定唯一写入者。独立 worktree 也不自动消除最终集成冲突。
7. 模型回复、测试脚本退出成功和任务状态是不同证据。PASS 必须绑定实际版本和可复查证据；部分通过不能包装为整体通过。
8. 用户确认、Tester PASS、开发继续和 Git 操作分别授权，不互相替代。
9. 中断恢复复用原任务、成果、证据和重试计数，不因重新启动 Agent 重置历史或重复开发。

### Buzz 必要适配

1. Buzz 只在入站边界认证消息作者、频道、线程、事件和目标 Agent；认证结果转换为不可由模型修改的 `IngressEvent`。
2. 新顶层线程选择项目后，工作流中的 `project_id` 不可变；回复继承已绑定项目，同线程切换项目在模型执行前拒绝。
3. 入站消息认证与长时执行授权分离。短期事件凭证不得覆盖整个模型或工作流寿命；每次产生副作用前重新核对持久授权、当前状态和目标版本。
4. 角色由工作流节点和服务端策略分配，不能由 Agent 名称、Persona 或消息正文自报；工具面由服务端 `CapabilityGrant` 裁剪。
5. Agent 不自行选择 Channel、reply root 或收件人。运行时产生 `WorkflowProjection`，Buzz Adapter 根据已认证关联发布到原线程。
6. Agent 间普通文字只表达进度、结果或请求；正式确认、状态转换和下一角色启动由运行时验证后执行。运行时尚未接管调度前，只允许本文第 9 节已确认的同任务有限自动返工过渡协议；它不改变权威状态，不启动新任务或下一 Phase。
7. Codex 与 Cursor 需要两个独立 Managed Agent 身份和运行记录；`BUZZ_ACP_AGENTS=2` 仅表示同一身份后的进程池，不视为两个独立角色。
8. 当前 Codex Desktop 会话不能被假定为 Buzz 中 Codex Agent 的延续。Buzz Agent 必须从落盘权威文件恢复，不继承本聊天记忆。

#### 第一门：运行时一致性

LangGraph 首先原样使用同一测试夹具覆盖以下场景；如果后续触发 Phase 3B，MAF 必须使用完全相同的夹具和通过条件：

2. 长于 100 秒的 Agent 执行后仍能安全提交；
3. 在人工确认点暂停并落盘；
4. 进程重启后恢复相同工作流；
5. 对同一 SHA 和用途明确确认后继续；
6. 错误 SHA、错误用途、错误项目和错误角色拒绝；
7. 重复 resume 不重复写入；
8. 写入后、状态提交前崩溃可以幂等恢复；
9. 两个工作流互不污染；
10. 旧版本或迟到结果不能覆盖当前版本；
11. Agent 自报角色、项目或工具不能改变 `ExecutionContext`；
12. 未获授权的工具调用在领域工具之前被拒绝。

- Agent 不持有路由选择权；
- Codex 与 Cursor 的真实命令、登录、工具和文件权限分别验证；
- 两个 Agent 可以围绕一个 `task_id` 完成一次开发—审查往返且不形成无限循环。

第二门通过仍不代表旧安全责任都已替代。

#### 第三门：等价边界

- 名单外项目在模型启动前拒绝；
- 同线程切换项目拒绝；
- 多事件不能错误共享最后一条事件上下文；
- 需求、Main、方案、Developer、Tester 只取得角色允许的工具；
- 模糊文字不产生正式确认；
- Buzz 与运行时重启后仍恢复项目和工作流绑定；
- 普通成功回复在 Channel 可见，拒绝、取消、空输出不伪装成功；
- 旧版本、旧线程、旧工作流和迟到 Agent 结果不能覆盖当前基线；
- 不依赖 Agent 自行发送消息或读取秘密；
- 每项边界能指出由哪段自有代码强制，而不是只由框架默认行为或提示词保证。

- 实际运行命令、退出码和通过/失败数量；
- 脱敏后的 checkpoint 或状态样例；

- diff 统计和既有脏文件保护结果；

#### Honey 恢复与日志压缩验收

- 首次完整冷启动形成判定后必须产生 schema 可校验、权威文件完整摘要可重算的恢复胶囊；同任务后续 attempt 更新 `last_attempt`、判定和 finding 列表。
- 胶囊路径只使用经过安全校验的 `task_id`，文件权限限制为当前用户；不保存原文、密钥、凭据、环境变量值、客户输入或 checkpoint 载荷。
- 文件缺失、摘要变化、schema/路径非法或 Git/任务基线不能对齐时必须退回完整冷启动；胶囊匹配不能自动宣告允许增量恢复。
- 成功命令的模型输出不包含逐用例 verbose 内容；失败命令只返回有界相关片段，同时在受控临时目录保留完整日志供定向复核。
- 辅助工具不经 shell 拼接命令，限制失败片段大小，对常见凭据形式执行二次脱敏，并能检测执行前后正式工作区 Git 状态是否变化。
- 单元测试只使用临时目录，覆盖胶囊原子写入/更新/摘要失配、安全路径、成功输出压缩、失败片段边界、日志保留与工作区变更检测；测试通过不等于 Buzz C 层历史已清理。
- 融合工作区的胶囊必须封入 `README → 00 → 02 → 05 → 03 → 06`、Honey 手册、helper `AGENTS.md`、当前项目 `AGENTS/CONTEXT/README` 和当前计划；缺任一文件时必须阻止可用胶囊和通过判定。
- 独立探针必须对完成条件动词建立可失败断言；恒真断言、只检查状态不变或只列强制点不能充当拒绝证据。E02 必须同时证明 `process_next() is None`、`resume`/模型/DomainTools/成功投影全为 0，以及原绑定与 revision 不变。

### 16.9 Runner 派发前的收敛项与停点

1. **范围选择**：建议先接一个真实运行环境完成 requirements/solution 两角色，再验证另一个环境的等价性；是否必须本任务同时接 Codex+Cursor，由 Bowen 确认。业务角色不能用 Fizz/Honey 的建设身份自动替代。
2. **调用协议**：定向复核现有运行环境的实际命令/传输、输入与结果、执行标识及状态查询能力；在不调用模型、不读取凭据值的前提下可继续只读核对。本稿不指定未经核实的 CLI 参数，也不要求用户手填内部参数。
3. **输入与权限**：落实需求输入来源、已确认 PRD 快照的读取接口、只读材料组装/大小限制及实际沙箱能力；如果需要新增 DomainTools 能力或额外文件，先回设计并精确列范围，不绕开现有工具自己读“最新文件”。
4. **等待与取消**：现有 AgentRunner 仅同步 `run`，Runtime 的工作流取消不等于在途模型进程已终止；需要明确超时、取消触达方式、退出等待上限、部分结果保留及未知结果的恢复。建议首版不自动重试、不在取消后接纳迟到结果；这些是待确认的体验/消费取舍。
5. **真实验证授权**：只读准备不授权模型费用、登录/密钥操作、常驻进程或 relay 成员变更。正式派发须给出允许的运行环境、临时项目、调用/费用上限、完整回归范围及资源归属；无权调用的项保持阻塞。

完成上述只读技术核对、关键取舍确认和精确接口/验收定稿后，再输出可直接交给 Fizz/Honey 的独立执行计划与准确授权正文。未定部分不当默认实现，也不把普通实现细节逐项转嫁用户。当前停在门禁准备稿，未启动任何 Runner、业务子角色或生产服务。
