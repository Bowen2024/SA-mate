## 2. 测试环境与夹具

### 2.1 隔离布局

所有写入测试使用系统临时目录。推荐保持部署相对关系：

```text
<临时根>/
├── install/
│   ├── Develop_Helper/                        # 受控上游副本／样例
│   └── fusion-runtime/workflows/
│       ├── requirements/                     # 原样基础模块、临时配置与锁
│       └── Solution Designer/                # 被验代码／规则／来源的准确副本
├── business/
│   ├── meeting-helper/                       # ASCII 目录项目 A
│   └── 会议助手/                              # 中文目录项目 B
├── outside/                                  # 越界哨兵与附加资料
├── client/mcp.json                           # 临时客户端配置
└── evidence/                                 # 结果、摘要和日志
```

foundation 指向 install 中 requirements，projects_root 指向 business，upstream_root 指向独立 Develop_Helper。两个 methods 链接解析到同一临时上游。测试只允许在临时布局生成临时锁定记录；真实上游和真实锁不刷新。

基础模块从当前受信 requirements 原样复制，记录摘要；不从旧 buzz-develop-helper 导入代码或签发器。上游漂移测试只改临时副本。不得移动真实旧目录来证明“无旧目录”，不得修改 HOME、CODEX_HOME 或用户配置来隔离。

### 2.2 基础样例

| 名称 | 要求 |
| --- | --- |
| A／B | 不同持久 project_id、路径和中文／ASCII 名称；B 用合法目录映射；均按当前共享项目结构初始化 |
| 需求 Q1 | 完全人工构造的测试正文；不复制 pirs-cursor-test 或其他真实项目 |
| PRD P1 | 2 个 REQ、至少 3 个 AC，包含成功／失败验收；每个 AC 明确归属；通过当前 PRD 结构检查；源需求摘要匹配 Q1 |
| PRD P2 | 相对 P1 的已知范围或 AC 变化，重新计算源绑定；用于旧确认和版本冲突 |
| 方案 T1／T2 | 0—12 唯一章节、完整七列覆盖，Lite／Standard／AI 三种 profile；T2 只改一个可定位设计段 |
| 确认 K1 | 完整登记、decisions 记录、固定 PRD 快照和反向确认引用；项目／内容／用途相符，阻塞项空 |
| 其他登记 G1 | 另一个非 PRD 条目，包含历史版本和 file-set 清单／成员；用于证明全登记校验保护 |
| 哨兵 S | 项目 README、project.json、源需求、PRD、确认／快照、外部文件、兄弟项目和临时客户端其他条目 |

P1 的结构须遵循实际 `requirements.inspect_prd`：用户结果与成功指标、具体案例、范围与边界、REQ 与 AC、业务流程图、业务时序图、事实／假设／待决、变更摘要；AC 含结果类型、前置条件、操作、可观察结果、验证方式。不可通过 mock 一个永远通过的 PRD 检查器制造正向样例。

K1 明确标记为离线测试夹具，仅按现有持久 schema 构造并由实际校验器核验。不调用旧 Main 私有方法，不模拟真实用户已确认，不把 runtime_authenticated=true 本身当宿主认证实测证据。

每个负向分支从独立干净夹具开始，原则上只改变一个条件。先验证正向基线，再破坏目标条件，避免参数错误／坏登记掩盖待测路径。

### 2.3 观察与故障注入

每次调用前后记录相关文件集合、原始字节摘要和必要元数据，不能只对返回值断言。只读测试前后所有业务文件、锁、临时文件和历史集合必须一致。

写入成功观察：目标正文／受管头／摘要、旧稿完整历史、输入与哨兵不变、锁释放和自有临时文件清理。失败观察：禁止范围不变，返回与实际副作用相符；not_written 不能暗藏目标替换，saved_unverified 不能假装完整成功。

时间测试使用可注入单调时钟，不真实等待 15 分钟。竞态／故障可在正式测试中使用局部受控 hook 或调用边界注入，但不得新增模型可控的故障参数或公开绕过接口。至少有一条正常保存经实际 stdio 和真实文件 I/O 完成。

Honey 的独立探针以公开入口和实际文件为主；故障细分可以核对正式测试的注入点、断言及真实文件结果。不能把 mock 返回成功、共享旧内存对象或未到达目标阶段的异常当所需证据。

## 3. 统一执行与判定

1. 核对准确用户范围、本文与实施说明版本、当前实际文件／修改、Fizz 报告和未关闭 findings。
2. 按下节映射选择本段全部适用用例。未来未交付部分记“阶段未验”；完整交付中的必需项不得借此跳过。
3. 核对样例满足前置；对每项执行公开调用、正式测试或明确标注的静态检查。
4. 同时观察返回和真实文件副作用，记录 code、write_outcome、read_id_consumed、被检查／保存的准确摘要。
5. 输出逐项通过／失败／未验／前置阻塞及证据位置；不适用须说明阶段或平台原因。

调用同时有多项错误时不强制未约定的优先级；要核对特定错误码，应先隔离其他条件。调用级错误、结构 issues、确认五态和写入结果分别判定。

权限越界、错项目写入、无效确认仍保存、覆盖新版本、破坏历史、误报写入结果、正常运行依赖旧目录，均是契约失败，不能用其他成功用例抵消。无真实确认来源仅阻塞步骤 8 对应范围，不能阻塞临时夹具代码验证。

测试日志应含工作目录、命令、退出码、测试数、失败／错误／跳过数、耗时及日志位置。0 tests、导入失败、意外 skip、只打印 true 不算通过。完整功能交付独立运行全部适用用例一次，随后无变化不为第二份报告重跑。

## 5. 能力、安装和目录：C01—C05

### C01 能力开关与实际分派

- **依据／范围**：实施说明第 3.1、16.3 节；5A 只读分支，5B 再验保存分支。
- **前置／操作**：用相同临时基础分别启动默认与 --allow-save 进程；实际 MCP initialize、tools/list、tools/call。默认进程直接构造保存调用；传入 allow_save、role、approval_verified 等未知参数。
- **预期**：5A 默认只列两个已实现只读工具；未交付保存不冒充可用。5B 完成后默认 2 个、允许保存 3 个，名称／schema 与契约一致；直接调用未开放工具失败，参数不能扩权。未知协议版本按实际支持规则拒绝或协商，不能伪造已调用。
- **文件／失败判据**：默认进程拒绝保存时目标、历史、锁、哨兵均未变化；出现隐藏可调用写入口或调用参数打开权限即失败。保留 catalog、拒绝结果及前后集合，不记录可复用 read_id。

### C02 持久身份、中文目录与目录映射

- **前置**：A／B 项目；B 的目录名与 project_id 不同，存在合法映射。
- **操作**：分别读取、检查；5B 用各自凭证保存。修改临时映射使其与持久身份冲突；再构造另一目录使用同一 ID。
- **预期**：返回准确 path／ID／identity_source，调用共享函数绑定 expected_root 和 directory_name。冲突为 identity_conflict 或明确目录拒绝；凭证不能借给另一目录。只读不初始化、不改 project.json。
- **证据**：两个项目的准确内容与摘要、调用结果、兄弟项目哨兵。仅比较目录名或输出 ID，未证明操作落点，不足以通过。

### C03 路径及文件安全边界

- **操作分支**：projects_root 本身、根外目录、嵌套孙目录、含 .. 的路径、相对路径、项目软链；项目内 docs／目标／历史／确认快照路径软链；非普通文件、目标硬链；非法 history_sha256 或伪装路径。
- **预期**：按实际入口在读取或保存前拒绝 path_not_allowed／unsafe_file 或明确参数错误；不跟随项目内链接读取越界正文，不写链接指向的哨兵。不接受大写／截断／带分隔符历史摘要。
- **观察**：根外文件字节、兄弟项目与合法目标保持；测试需覆盖各类路径，不能用“目录不是项目”这一更早错误代替文件边界验证。平台不支持某文件类型时记录环境和替代覆盖，不静默 skip 必需安全条件。

### C04 固定加载、来源和旧布局拒绝

- **操作**：正常启动后核对真实 module.__file__；在业务目录／当前目录放同名 requirements、solution 等诱导模块。分别缺一个共享文件、改一个采用源摘要、仅提供旧 upstream 布局、改临时上游内容；无正式代码修改。
- **预期**：使用专用包命名空间和固定文件；没有通用 sys.modules 替换或旧 scripts 回退。分别给 dependency_missing／dependency_changed／foundation_invalid／upstream_changed 等准确原因。
- **观察**：模块原点、子进程实际运行及拒绝；不能仅搜索源码没旧字符串就通过。漂移不能自动刷新真实或临时运行中的锁。缺 Git CLI 等实质边界依赖时明确失败，不悄悄跳过项目边界检查。

### C05 双方法入口与规范选择

- **操作**：两个 methods 指向同一临时上游为正向；分别断开、错指一个入口、改调研模板链。规范字段分别缺失、null、合法名称、非法名称／不可读目录；规范目录内放越界链接。
- **预期**：方法入口异常拒绝，不因另一入口正常放行。规范 missing／none／selected 不混同；合法名称返回清单和正文，缺失不默认 default。非法／不可读规范明确诊断；5B 不允许降为 none 后保存。
- **观察**：方法链接、规范解析目录和文件摘要、project.json 不变。规范不可读测试需有真实读取失败或明确拒绝路径，不能只 chmod 后在有更高权限的进程中假定不可读。

## 6. 读取、保护和凭证：R01—R05

### R01 核心材料存在状态与完整正文

- **操作**：基线读取六文件完整正文。分别移走 PRD／方案／需求、将已有目标置空、破坏 UTF-8、使文件不可读、破坏 project.json JSON；对有效身份与身份失败分开测试。
- **预期**：present／missing／unreadable／invalid 与原始字节一致，空文件有真实空摘要而非 missing。身份未持久时 project_not_initialized；其他可读材料允许讨论，不能伪造完整可保存基线。
- **凭证**：目标首次缺失可签发稳定版本引用；必需文件不可读或依赖不完整时 read_receipt=null，附原因。PRD 未确认但闭包稳定时可签发引用，save_eligible_at_read=false。
- **观察**：完整正文不截断、各输入摘要、状态与集合；无历史、锁、初始化和配置副作用。

### R02 完整依赖集合与变化拒绝

- **前置**：P1／K1／G1，已选合法规范；确认全登记校验可通过。
- **操作**：读取后，独立改变 project.json、README、requirements、PRD、目标、decisions、当前确认快照、其他登记历史文件、file-set 清单、成员；再测试成员增删与规范文件增删。每个分支重新建夹具。
- **预期**：每项在 protected_versions 中或按规范成员清单保护，路径作用域明确；集合／摘要变化使旧引用不能保存。依赖无法枚举时不签发保存引用。不能只查 PRD 与目标。
- **观察**：已返回集合、独立计算的原始摘要、5B 拒绝结果与目标不变；用静态调用分析和针对各类依赖的探针证明共享校验读取闭包都被覆盖。

### R03 普通附加材料与历史边界

- **操作**：为历史建立真实合法摘要，读取旧稿；放置外部附加文本、旧 docs/solution.md 和未选规范。传 additional_paths／target_path 等未开放字段；5B 比较凭证对当前目标与历史的预期。
- **预期**：工具不提供任意路径读取，拒绝未知参数；附加材料不进入强制保护声明。历史正文摘要核对准确，但不替代当前目标基线。外部资料变化不被误报“已受锁内原子保护”。
- **观察**：当前方案和所有输入完全未改；若历史损坏／缺失，按历史错误拒绝该请求，不用坏历史签发引用。

### R04 凭证时效、容量、进程和消费

- **操作**：注入时钟，在 900 秒前和满 900 秒检查；签发 65 个引用；跨 A／B、重启进程、跨 requirements MCP 借引用；重复调用 inspect，随后尝试保存。
- **预期**：满 900 秒到期，按签发顺序淘汰至多 64 个；跨项目、旧进程／其他服务引用无效。inspect 不消费、不续期、不换发引用。全局容量不能通过创建大量项目缓存绕过。
- **5B 消费表**：未知字段／未开放／无副作用预检失败为 false；内核入口前消费后，锁冲突、unchanged、保存成功、写入失败均为 true。重试已消费引用必须失败，不能为了重试恢复。
- **观察**：错误码与 read_id_consumed、实际锁／历史／目标。不真实等待 15 分钟，不将私有字典布尔值当唯一证据。

### R05 读取期间变化与非原子限制

- **操作**：在第一次集合采集与第二次采集之间改 PRD、快照或清单成员；分别改内容、加删路径、改规范目录成员。构造检查点间短暂改变再恢复的 ABA 示例用于核对声明。
- **预期**：可观察变化在 changed_during_read／consistency 中报告，无保存凭证；不得自动重读后悄悄把旧材料变成稳定候选。atomic_snapshot=false。
- **限制**：不要求摘要前后完全恢复的 ABA 必然检出；文档和返回不能宣称排除了所有外部编辑窗口。不用这个限制豁免可观察持续变化。
- **证据**：注入时点、前后版本、实际返回和无业务副作用。

## 8. 确认核验：A01—A02

### A01 五态和保存门槛

- **前置**：K1 通过实际本地校验，保存前其他输入均合法；5A 只测读取／检查，5B 再验证拒绝和正向保存。
- **分支**：valid；无 decisions／无匹配记录为 missing；准确旧 PRD 确认为 outdated；坏 JSON、登记反向引用丢失、摘要／快照错误、阻塞项非空为 invalid；校验能力不可用为 unavailable。另测错项目、错用途、非 PRD 对象、多个 valid 与旧／错用途记录并存。
- **预期**：只接受当前项目、当前 P1 摘要、精确用途“形成技术方案”的有效记录。错项目／用途为 ignored，不满足资格；存在真正 valid 时不因另一 ignored／旧记录把它覆盖。五态及 reasons 不被统一折叠为“未确认”。

### A02 读取、锁内和写后的再次核验

- **操作**：先读到 valid，分别在预检前、获取锁后、替换前、替换后改 decisions／登记／快照。通过受控检查点让变化确实发生在目标阶段，保持其余条件稳定。
- **预期**：替换前发现失效拒绝目标写入；内核前消费为 false、内核后为 true。替换后确认／依赖变化返回 saved_unverified，不能说输入始终有效或盲目重写。锁保护只约束遵循共享约定的写入方。
- **观察**：保存阶段、实际目标、历史、变化输入和后续引用；不能只 mock 最终确认返回 invalid 却从未进入写后路径。

## 9. 保存、历史与恢复：W01—W08

### W01 首次、重复与修改保存

- **操作**：P1／K1／目标缺失，读引用后保存 T1；复读、重取引用、同正文同 profile 再存；再读并存 T2。
- **预期**：依次 saved、unchanged、saved。首次没有虚构旧稿历史；重复不重写目标、不制造历史；修改后的历史以 T1 完整文件字节摘要命名并原样保留。头部 Draft／false、profile／PRD／确认 ID 来自实际核验。
- **观察**：独立原始字节摘要、正文、头部、历史集合、mtime／文件标识等辅助不重写证据，输入／哨兵不变。若文件系统时间精度不足，结合替换调用计数和集合观察，不只比较 mtime。

### W02 确定性渲染与元数据变化

- **操作**：同正文仅改变合法 profile；合法增加确认 ID；从未选规范改为显式 none／合法 selected 并重读；正文尾部换行变体。所有输入变化均以新基线提交。
- **预期**：受管字段变化导致完整版本变化且旧稿保留；排序去重确认 ID，重复相同条件产生相同字节，不插时间／随机版本。只规范化末尾换行，其余正文不改。
- **观察**：submitted_content_sha256、normalized_content_sha256 与实际正文一致；规范 missing／none／selected 保存状态可区分。不能以相同正文掩盖新元数据，也不能每次写入制造随机历史。

### W03 版本冲突、并发新建与锁顺序

- **操作**：读取目标缺失后另行创建目标；读取已有目标后另行修改；分别持公共锁、方案锁，尝试保存；模拟两个合法保存调用竞争。
- **预期**：旧目标预期不匹配即拒绝，不覆盖并发稿。固定公共锁→方案锁顺序，无自动删锁／解锁他人锁。锁内再次比较输入和目标。消费值与检测阶段一致。
- **观察**：失败返回、目标与历史、现有锁身份／字节以及兄弟项目。两个请求不能都凭同一旧基线覆盖成功；不要求未约定的线程调度顺序。

### W04 历史读取、冲突及旧稿恢复

- **操作**：保留 T1／T2 历史，合法摘要读取；同摘要历史已存在一致／已存在坏内容；历史缺失／非法摘要／路径软链。明确恢复 T1 时取其正文、剥受管头，按当前 P2 和合法确认形成新候选后保存。
- **预期**：历史只读且摘要匹配，不重命名／修补坏历史。旧头／旧确认不恢复效力；恢复保存使用当前目标预期与当前 PRD，归档被替换当前稿。完整文件摘要可能与 T1 不同，不能因此误判恢复失败或声称旧确认复活。
- **观察**：T1／T2 原历史保持、当前新正文、当前元数据与原输入，报告恢复时的必要设计差异。

### W05 故障阶段与五种结果

- **操作／预期矩阵**：

| 注入阶段 | 预期分类与实际观察 |
| --- | --- |
| 无副作用预检失败 | not_written、未消费、目标／历史／锁未变 |
| 内核进入后获取锁失败 | not_written、已消费、不得删除已有锁 |
| 历史创建后、目标替换前失败 | not_written、已消费，披露真实 history_created；目标仍旧稿 |
| 临时写／持久化失败且可证明未替换 | not_written，临时／清理副作用准确 |
| 原子替换完成后复读／输入／历史核对失败 | saved_unverified；目标确已改变，失败项明确 |
| 写辅助跨替换点异常，无法可靠判断是否替换 | unknown，字段未知用 null 和理由；禁止盲重试 |
| 目标已核实但结构检查器异常 | 保存结论保留，inspection.status=unavailable |
| 替换完成后锁被替换／释放或自有临时清理失败 | saved_unverified，保留目标已写事实及具体清理问题 |

- **核对**：每个分支证明注入点到达，核对原始目标／历史／锁／临时文件以及 read_id_consumed；saved、unchanged 正向证据由 W01 提供。不把任意抛异常都归 unknown，也不强行要求无法观察的保存阶段产出已知布尔值。
- **恢复**：unknown／saved_unverified 后先通过读取核对，不直接重复提交。测试夹具残留只按临时目录管理，不能把自动删正式锁当恢复功能。

### W06 登记依赖目标重叠与未完成事务

- **前置／操作**：将已有 tech-spec 作为直接登记单文件／file-set 成员／确认快照依赖，登记先保持有效；分别提交相同字节和变化字节。另构造公共事务日志存在、软链或格式不可判的分支。
- **预期**：完整 unchanged 可在所有输入有效时返回；变化稿 target_bound_to_registry，不能剔除目标依赖或改登记后继续。事务存在即 transaction_pending，不由方案恢复、删除或前滚。
- **观察**：目标／登记／清单／快照／日志均保持原样，拒绝报告可定位对象。只有坏登记导致更早失败的样例不算目标重叠分支已覆盖。

### W07 源需求绑定与规范门槛

- **操作分支**：P1 正确绑定 Q1；PRD 显式绑定 missing 且源需求确实缺失；绑定字段缺失／格式坏；Q1 修改／删除／新增而 PRD 未同步。规范分别 missing／none／selected，合法选择后内容变化／不可读。
- **预期**：前两种在其他条件合法时可保存；缺绑定／坏绑定／不一致分别明确拒绝。缺字段旧 PRD 可读取讨论，不自动补头。规范未选允许 Draft 并报告；非法／不可读指定规范不自动降级。读取后选择或正文变化使旧凭证冲突。
- **观察**：source_alignment、保存 code、PRD 与 project.json 完全不改；每个分支重建匹配确认，避免旧确认失效掩盖来源门槛。

### W08 保存事实与结构结果分开

- **操作**：合法 P1／K1 下提交带明确 open／blocked、遗漏章节或不完整覆盖字段的非空候选；另让保存后检查异常、检查期间目标又变化；对照无效前置 PRD／确认分支。
- **预期**：候选结构 issues 可以保存 Draft 并附准确检查问题；不得一律转 content_invalid。无效 PRD／确认不能被候选检查 pass 放行。检查器异常与保存事实分开，checked_file_sha256 必须匹配被检查版本；后续变化明确说明。
- **观察**：当前正文、元数据、目标复读证据、inspection 状态／摘要；不因结构问题重复保存或自动修补正文。

## 10. 资源边界：P01

### P01 字节、消息、返回和依赖预算

- **依据**：实施说明第 4.3、8.1／8.4 节；各阶段只测已交付分支。
- **操作**：按 UTF-8 字节生成临界值，不按字符数。最终渲染稿 128 KiB 上下、单文件读取边界、1 MiB 消息、512 个唯一文件与 64 MiB 总依赖预算、返回正文 1 MiB 上下；覆盖重复路径去重与多字节中文。记录校验器原有各类上限用对应输入验证。
- **预期**：未超过上限可按其他条件处理；超过则准确拒绝／无凭证，不截断文件、正文或依赖集合，不分段后冒充完整读取。最终文件限额包含工具生成头，不能只验证 content 长度。
