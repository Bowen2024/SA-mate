# 阶段 R：按需竞品调研

在用户要求调研，或产品定位、功能取舍、关键交互需要外部参考时进入。复用已知的用户、场景和痛点，只补问影响这次比较的问题。

## 一、限定工具类型

联网调研只使用当前环境已经提供的以下两类工具；工具名称以实际可用列表为准，不要求安装同名工具。

| 工具类型 | 可执行动作 | 获取的信息 |
| --- | --- | --- |
| 网页搜索，如 `web_search` / `WebSearch` | 搜索产品、官方介绍、帮助中心、使用指南；限定官网域名查具体问题 | 候选产品、来源链接、搜索结果中的相关说明 |
| 网页正文读取，如搜索工具自带的打开页面能力或 `web_fetch` / `WebFetch` | 读取已知公开 URL 的正文，核对搜索结果；已有能力时按需使用 | 功能范围、操作步骤、配置条件、限制与原文依据 |

- 本阶段不安装依赖、不下载或启动浏览器，不使用 Playwright、Selenium、浏览器自动化 MCP、终端或脚本抓取网页。读取用户已有资料、读取本模板和回写 PRD 使用普通文件工具。
- 只有搜索能力时，依据可见结果工作并标注“仅搜索摘要”；无法获取的细节标为“未核实”。网页无法读取或需要登录时，不绕过限制。
- 没有联网搜索能力时，只整理用户已提供的资料并说明缺口，不声称完成联网调研，也不自动安装替代工具。

## 二、按问题检索与提取

先写明本次要支持的决策，例如“是否需要多角色协作”，再按下表执行；已有产品名或可靠资料直接复用。通常比较两款即可，面向国内用户时优先包含国内案例。

| 步骤 | 工具与动作 | 提取内容 |
| --- | --- | --- |
| 找到可比产品 | 网页搜索“用户场景 + 产品”，或“产品名 + 官网” | 面向谁、解决什么任务、为什么值得比较；不按搜索排名直接判定优劣 |
| 还原核心流程 | 搜索“产品名 + 目标功能 + 使用指南”；按需读取官方介绍或帮助正文 | 用户输入 → 关键操作 → 得到的结果，以及涉及的角色 |
| 核对功能边界 | 搜索“site:官网域名 功能名 限制/配置”，按需读取相关正文 | 支持与限制、前置条件、配置方式；仅在影响本次选择时查价格或套餐 |
| 了解交互安排 | 搜索并读取官方操作说明或界面介绍 | 明确描述的入口、页面组织、反馈方式；纯文字检索不支持对实际视觉效果作出判断 |

以官方资料为主要依据；第三方评价只能标明出处后作为补充。为关键事实记录页面标题、URL、访问日期和证据范围。未找到某功能不等于产品不支持；功能取舍的原因若无来源，明确写为分析推断。

只围绕影响本次决策的缺口补搜。信息足以支持比较时结束；公开资料不足则保留未知项，不为了填满表格扩大调研范围。

## 三、按模板形成建议并交接

读取 [竞品调研模板](references/research-template.md)，在对话中输出简短比较、证据、建议与待定项。将竞品事实和本项目建议分开，不因竞品有某项功能就加入项目。影响项目方向的取舍需要用户决定，已有选择不重复确认。

将采用的结论与来源写入 `docs/PRD.md`（路径：`<active_project_path>/docs/PRD.md`）的“用户目标与完整流程”或“界面约定”，回到 [阶段 A](phase-A.md) 继续需求与验收。仅在用户要求独立调研报告时，保存为 `docs/research.md`（路径：`<active_project_path>/docs/research.md`）；已有指定文件时沿用其路径并给出绝对位置，不重复建报告。
