# 使用与接入

更新日期：2026-11-03。本仓库目前可用于理解架构、阅读 SDD 方法及核对历史设计。三个角色的 MCP 源码尚未发布，因此本页提供当前使用方式和待交付的接入条件，不提供无法在本仓库执行的安装命令。

## 先理解当前使用方式

用户明确角色、项目与目标；Agent 读取该角色的规则及适用方法，围绕目标推进。需要保存时再使用实际连接且具有相应能力的 MCP 工具。

以下是已安装、已核对工具环境中的请求示例，路径需替换为实际项目目录：

> 按需求角色，读取 `/绝对路径/业务根目录/项目A` 的需求，讨论需要修改的范围。

> 按方案角色，读取这个项目的 PRD，讨论实现设计。

> 按 UI 角色，根据这些页面与场景说明制作独立演示。

仅讨论无需先初始化项目。需要写入时应明确成果归属和操作意图；已有项目读取实际文件与版本后继续。新聊天重新明确项目位置并读取相关成果。

当前工具仍要求项目位于配置业务根目录的直接下一层；完整路径参数不表示已支持任意位置。切换项目时每次调用传入相应路径，不要求逐项目注册 MCP。

## 代码发布后接入需要具备什么

| 条件 | 要核对的内容 |
| --- | --- |
| 角色入口 | 需求、方案、UI 各自唯一主文档及文件操作约定可读取 |
| 方法与模板 | Develop Helper 方法入口、相邻引用与本地模板可访问 |
| 公共基础 | requirements 共享模块、配置及来源锁完整；方案与 UI 加载器采用对应基线 |
| 客户端连接 | 实际客户端支持的 MCP 配置与启动参数；不得把另一客户端的配置直接套用 |
| 文件权限 | 工具安装位置、上游方法及本次项目在宿主允许的访问范围内 |
| 操作能力 | 默认只读与显式初始化／保存／UI 写能力分别配置；聊天文本不能增加工具权限 |
| 验证 | 先检查和读取隔离项目，再验证保存、冲突、历史与恢复；业务项目只在明确范围内操作 |

不需要安装工作流框架或启动协作宿主。当前角色服务分别连接，代码复用不等于必须同时启动全部服务。

方案工程保存还需要有效的 PRD 用途确认，普通“同意”回复和工具能力开关不能替代确认核验。独立环境中受信确认写入入口仍有缺口，详见[当前状态](current-status.md)。
