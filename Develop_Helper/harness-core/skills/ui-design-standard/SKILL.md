# 项目设计风格

从用户需求中分析设计问题、提取设计要素、形成一致的视觉方案，产出项目 `docs/ui-style.md`（路径：`<active_project_path>/docs/ui-style.md`）。本 Skill 独立完成设计分析，不依赖其他设计 Skill；不制作原型或业务代码。

由阶段 B 在需求和七层技术方案已明确后调用；不因用户刚提供模糊需求就启动界面设计。沿用上游已确定的 `active_project_path`，读取 PRD（路径：`<active_project_path>/docs/PRD.md`）。项目未明确时先定位目标项目，不使用当前工作目录代替项目路径；本 Skill 的 `references/` 只存通用模板，生成的文档归入目标项目。

## 一、分析设计目标

读取 PRD 中相关需求、用户场景和目标设备，明确用户最常做什么、最需要看清什么，以及信息密度、品牌、语言、性能和可用性约束。已有明确的设计或用户提供的参考直接作为输入，没有参考也能继续。

只澄清会改变设计方向的缺口；已确认的风格和产品决定直接沿用。输出一句体验目标及少量关键约束，不另外生成过程文件。

## 二、提取设计要素

从需求、内容与已有界面中提取下列要素，说明它们对本项目的具体影响：

| 要素 | 要分析的问题 | 要形成的设计决定 |
| --- | --- | --- |
| 任务与信息层级 | 主任务、主要动作和辅助信息是什么 | 视觉焦点、主次操作、导航及分区顺序 |
| 内容与阅读 | 文字、数字、图片或对话各占多少，是否密集或很长 | 字阶、行长、密度、内容容器与滚动方式 |
| 布局与空间 | 信息如何分组，不同设备怎样容纳 | 栅格或分栏、宽度、间距、留白与响应式变化 |
| 风格与识别 | 需要传达什么气质，哪些品牌特征值得保留 | 统一的视觉方向、色彩关系、字体气质、形状与层次 |
| 组件与反馈 | 重复操作有哪些，用户何时等待、失败或无法操作 | 复用组件、主次层级、加载/空/错误及适用交互状态 |
| 使用约束 | 输入设备、阅读需求、长内容与性能有什么限制 | 焦点、触控、文字可读性、适配和必要的动效边界 |

只展开项目涉及的内容：落地页重点分析内容顺序和主要行动，数据界面分析数据比较与图表，对话界面分析角色、消息和等待反馈。不要为凑清单增加功能。

## 三、形成统一的设计方案

将提取结果归纳为一套视觉方向，并说明关键取舍怎样服务用户任务。把主色与强调色、标题与正文、信息密度与留白、圆角与层次配合起来，不独立拼凑每一项。

已有设计时保留有效部分，只调整本次问题涉及的内容；没有已定方向时给出有理由的建议。风格鲜明程度、装饰和动效服从项目需要，简洁界面同样通过层级、比例和细节形成一致性。

## 四、落实全局规则与页面设计

仅在编写文档时读取 [设计风格文档模板](references/ui-style-template.md)：

- 将视觉决定落实为可实现的配色、字阶、尺度、形状、层次和状态取值，集中写全局规则。
- 由 PRD 的 REQ / AC 推导本次页面（旧项目沿用原 ID），每页写清任务、信息阅读顺序、主要操作、内容排列与必要状态。简单页面可简写，但不能只写边距、按钮尺寸或“成功绿字”；不能只详细设计主页面，其他页面用占位说明带过。共用值引用全局规则。
- 明确共用外壳、独立页面与导航关系，以及内容高度、滚动区域、输入或操作区位置和窄屏变化。列表需说明列或行内层级、对齐与长内容处理，不为填满布局增加搜索、筛选等未要求功能。
- 每个操作区域按当前状态突出主要动作，写明关键操作前后的可见变化；区分普通提交与草稿确认，避免歧义或重复主按钮。界面使用用户能理解的业务名称，技术枚举留在数据契约中；技术计数仅在有助用户判断时展示，并解释含义。
- 产品功能、权限和业务交互仍由 PRD 定义，风格文档说明这些要求怎样呈现，不另设业务规则。

输出 `docs/ui-style.md`（路径：`<active_project_path>/docs/ui-style.md`）；已有文件只改受影响章节，交付时给出完整绝对路径。分析结论进入文档，不另建调研报告、要素清单或过程记录。

## 五、检查与交接

检查每项关键设计是否有任务或内容依据；每页是否覆盖信息层级、操作结果、必要状态与长内容；导航、滚动和适配约定是否明确；全局值、正文、页面是否一致，字体是否有回退。本 Skill 只报告文档检查结果，实际页面与交互验证由阶段 B 执行；未实际查看不能宣称视觉验收通过。

风格文档与原型（如有）在阶段 B 合并确认，不重复确认未改变的 PRD 或技术方案；已有确认直接沿用，确认后标为 `Confirmed`。PRD 链接风格文档，Planner 将相关全局与页面章节放入任务 `context_files`，供原型、开发和测试共用。

`ui-style.md` 是项目设计产物，与开发规范集分开。`specification: null` 时仍可设计界面，`rules_files` 仍为空；纯 API / CLI 项目无需生成。
