# 开发共同约定

## 输入与规范

- 需求、业务规则和验收以确认后的 `docs/PRD.md` 为准；实现和接口以确认后的 `docs/tech-spec.md` 为准。
- 读取 `.sdd/project.json` 的 `specification`：集合名称表示按当前任务加载对应文件，`null` 表示不加载规范集。字段缺失或配置冲突时先澄清，不自动回退到 `default`。
- 技术栈由项目技术方案和所选规范共同确定，不在本协议锁定语言或框架。任务的 `rules_files` 只列实际需要的文件；未选规范集时为空。

## 实现与验证

- 修改前阅读相关代码。按任务验收要求执行必要的安装、构建和测试，报告实际结果。
- 前端优先按已确认接口契约实现页面与 Mock；后端随后实现并由指定后端/联调任务完成真实用户链路。前端阶段通过不等于业务 AC 通过，最终回归不能替代业务任务的真实验收。后端开发期间可并行调整前端样式，写入范围与共享文件归属由编排器协调。
- 缺外部服务配置或权限时，明确阻塞或经用户接受的降级范围。Mock 通过不能算真实服务验收通过。
- 密钥只保存在用户指定的安全配置中，设计文档、任务、报告、日志和经验只记录配置名称与状态。
- 用户已授权的操作继续执行；需要额外权限、不可逆变更或未授权的外部发布时，说明具体操作和影响后取得授权。

## 状态与交付

- `.sdd/tasks.json` 由编排器统一维护任务状态。Developer 和 Tester 返回结果与证据，不直接更新任务状态。
- 确认节点、有限修复和 BLOCKED 处理按 [开发循环](development-loop.md) 执行，本文件不重复定义状态机。
- 完整项目计划以 [页面功能导航交付](project-delivery.md) 作为最后一步，Developer 实现、Tester 验收。全部约定任务及必要验收完成后，在项目 README（路径：`<active_project_path>/README.md`）提供运行说明、验证结果及 HTML 入口（路径：`<active_project_path>/docs/project-console.html`）；尚有阻塞时明确未完成范围。HTML 展示经源码核对的页面功能与实现，不维护任务进度。
