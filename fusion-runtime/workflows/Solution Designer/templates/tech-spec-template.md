# 统一技术方案模板

本模板用于 `docs/tech-spec.md`。Lite、Standard、AI 共用一份结构，通过展开程度区分；不复制三份容易漂移的模板。

```yaml
---
artifact_kind: tech-spec
status: Draft
approval_verified: false
profile: Lite | Standard | AI
prd_path: docs/PRD.md
prd_sha256: <实际摘要>
prd_confirmation_ids: [<Main 核验的“形成技术方案”确认 ID>]
---
```

## 0. 基线与用途

## 1. 用户结果与覆盖范围

- 引用 REQ/AC；不重写业务需求。
- 概括用户输入 → 系统处理 → 用户结果。
- 同时列成功和关键失败结果。

## 2. 系统边界与接口

- 参与者/模块边界：

- 每个真实接口使用稳定 ID，并说明来源 REQ/AC、请求、成功、失败、鉴权/权限和幂等。
- Lite 没有网络接口时描述真实命令或模块边界，不虚构 API。

## 3. 数据与生命周期

- 字段/类型/单位/校验：

## 4. 模型、提示词与工具

- 无 AI：写“不适用”及原因。
- AI：模型职责/版本或选型条件、提示词位置、动态输入、输出约束、解析校验、工具参数与权限、评估集、质量阈值、回退与人工复核。

## 6. 异常、重试与恢复

- 触发条件 → 错误/状态 → 用户可见结果 → 重试/恢复 → 资源清理。
- 覆盖校验、业务、外部、超时、重复与降级。
- AI 配置覆盖模型拒绝、格式错误、质量风险和工具失败。

## 8. 技术时序

- 使用实际前端、后端、模型、工具、存储和外部服务参与者。

- 业务时序留在需求成果，本节通过 REQ/AC 关联。
