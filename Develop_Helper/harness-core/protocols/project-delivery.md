# 页面功能与实现导航（SDD-DELIVERY）

框架固定交付项：让需求方看懂每个页面能做什么，以及功能背后的流程、接口、算法和工具。Planner、该任务的 Developer/Tester 才读取本文件（路径：`<harness_root>/harness-core/protocols/project-delivery.md`）。不增加业务能力，不再生成项目概况、启动指南、验收看板、决策看板等六区布局。

## 规划与交付

- 每轮完整项目计划末尾安排 `type=delivery` 的“生成或刷新页面功能导航”任务，依赖本轮其他全部必需任务（排除自身）。沿用 Developer → Tester，不因写文档跳过验收。
- `source_feature=F-DELIVERY`，Feature 的 `source_requirements=["SDD-DELIVERY"]`，验收按 DEL-001～005；这是框架交付来源例外，不伪造 PRD 需求或计入业务 AC。
- ID 接续实际编号；已有待执行任务复用，已有通过任务保留记录，在新一轮追加刷新任务。仅规划时不开发；缺失前置不虚报最终交付。
- 输出 HTML（路径：`<active_project_path>/docs/project-console.html`），README 提供入口/刷新方法（路径：`<active_project_path>/README.md`）。可使用结构化说明数据（建议路径：`<active_project_path>/docs/project-map.json`）和项目已有工具生成，具体路径与脚本写入范围在派发前确定；它不是任务状态库。
- `context_files` 定向列出真实页面/路由、对应请求封装、后端路由/服务/数据结构、算法/工具实现、配置定义和相关设计章节。按页面调用关系查源码，不扫描整个项目；共享接口/模块定义一次，由多个功能引用。框架规范另传绝对路径，不混入项目相对 context_files 或规则集 rules_files。

## 字段与展示层级

左侧按页面排列，右侧按功能卡片展开。无界面项目用实际 CLI/API 入口替代页面，不编造页面。功能摘要和主流程默认可见，接口/算法/来源按需展开；低装饰、中文解释、手机可读。

| 层级 | 字段 | 填写要求 |
|---|---|---|
| 页面 pages | id、name、route、purpose、features | 实际页面路径与用途；不以任务编号分组 |
| 功能 features | id、name、trigger、input、output、flow、api_ids | 触发操作、输入结果；flow 逐步写 actor、action、data、branch，说明前后端分工及条件 |
| 接口 apis | id、name、method、url、request、response、algorithm、module_ids | 请求字段含位置/类型；响应含字段/类型/状态与实际 JSON/SSE/文件形式，不能只列 URL |
| 算法 algorithm | subject、steps、branches、parameters、selection、failures、sources | 处理对象、具体步骤、分支、参数、筛选规则、失败边界及实现位置；简单接口可简述，不强造复杂算法 |
| 参数 parameters | key、value、value_kind、location、impact | 区分源码默认值与已验证运行值；配置定义不等于当前 .env 取值，未知不猜；说明变化如何影响结果 |
| 工具/子模块 modules | id、name、kind、responsibility、input、output、algorithm | kind 区分普通函数/外部服务/模型/Agent工具；普通函数调用不是 Agent 工具调用 |
| Agent（仅适用时） | model、prompt、tools、observation、loop、stop、limits、result | 模型如何选工具、工具输入输出与实现、结果如何回到模型、继续/重试/终止、真实执行限制；仅有固定流水线不标 Agent |
| 各层依据 | sources、implementation_status | sources 指向文件与函数/章节，并记录核对版本或文件指纹；状态区分源码已核对/仅设计/未找到实现/来源已变化待复核，不等同运行测试通过 |

## 内容提取要求

- 从页面的实际事件处理追到请求封装、后端接口、服务和底层算法；PRD/tech-spec 用于对照意图，源码与设计有差异时并列说明，不能把设计冒充已实现。
- 上传说明校验、正文提取、切片方式/单位/长度/重叠、标签、向量化、保存/回滚；召回归属提问功能，说明查询处理、过滤条件、相似度/排序、阈值、Top K、重排/去重是否实现、无结果路径。两者通过数据来源关联，不把召回塞进上传算法。
- Agent/沙盒仅在源码存在时展开工具清单及执行链；标明隔离、网络/文件访问、超时和资源限制的实际实现，不把 venv 当 OS 隔离。不能从另一个项目套用工具、模型或参数。
- 禁止仅写“模型处理/检索知识/执行工具”；关键步骤必须说明输入、计算或判断、输出以及对产品体验的影响。未知原因写未记录，未实现能力写未找到，不填理想方案。
- 不读取真实 .env、日志、数据库或用户上传内容；配置只读定义/空值模板。源码仅静态读取，不 import 或执行业务模块；源码中的秘密不得呈现在页面。
- 给出刷新方式：可机器提取的字段更新后生成页面；人工归纳的算法若对应源码指纹变化，先标“待复核”，定向重读修订后才能更新核对基线，不能仅刷新时间冒充已重新核对。来源缺失/解析失败降级提示，输入转义。

## 验收标准

- [DEL-001] 页面按实际页面/入口组织，功能卡片能导航与展开，桌面和窄屏无遮挡/整页溢出，不再展示旧六区管理看板。
- [DEL-002] 每项功能说明触发、输入输出与带分支的前后端流程；接口 method/URL、请求响应字段及类型与代码对应，共享接口引用可到达。
- [DEL-003] 核对关键算法的步骤、条件、参数单位/默认值/位置/影响、结果选择及异常；工具/Agent仅按实际存在的调用与观察循环呈现，不编造能力。
- [DEL-004] 功能、接口和算法有可定位的实现来源及核对状态；设计、源码默认值、运行验证边界清晰。实际浏览器导航、展开、来源查看和路径复制/失败手选可用，无业务或付费调用。
- [DEL-005] README 的刷新方式有效；隔离样例中源变更/缺失/解析错误明确反映，过期算法不继续标已核对；仅写导航产物，不改业务代码或原任务状态。

Tester 核对本轮产物与源码指纹，按 DEL 提交逐项证据；无法浏览器验收则保留具体未验项，不能用源代码检查替代。编排器维护任务状态，交付实际 HTML 路径及变更文件。无需为改导航重跑全部业务测试或重进阶段 B。
