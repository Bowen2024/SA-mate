# 项目开发管理

## 一、先判断项目意图，再确定项目路径

### SDD项目管理法则

结合用户请求和已有对话，判断是修改已纳管项目、纳管现有项目、从零创建项目，还是删除/重置项目。对于已有项目，先确认是否已被本套 SDD 纳管；从零创建不属于纳管现有项目。

本套 SDD 的项目管理方式如下，`harness_root` 是包含 `harness-core/` 和 `project-registry.json` 的 SDD 根目录。

- `Projects_Repo/<project-id>/`：已纳管业务项目的目录，位于 `harness_root` 下；每个项目有独立的代码、文档和状态。
- `project-registry.json`：根目录的项目注册表，记录项目的 ID、名称和路径；其中 `active_project_id` 是注册表保存的活动项目 ID，供用户未明确指定目标时参考。
- `Projects_Repo/<project-id>/.sdd/project.json`：项目自身的身份信息，用于与注册记录核对。注册记录、实际目录与身份信息一致，才能确定目标是对应的已纳管项目；目录存在不代表已经纳管。
- `active_project_path`：本次目标项目的绝对路径。后续业务文件读写和命令执行均以此为基准；确定这个路径即可开展当前工作，无须先更新注册表的活动项目。

### 意图类型

#### 纳管项目

用户要求将现有项目接入 SDD 时触发，例如“请把这个项目搬进系统中”。用户要求修改一个尚未纳管的已有项目时，先进入纳管分支，建议用户授权接入。

确定原项目的绝对路径；用户已提供时直接采用，缺失时请用户提供。原路径是接入来源，纳管后的目标路径由纳管流程确定。

#### 创建项目

用户明确要求从零创建项目时触发，例如“请帮我构建一个新的预约系统”。结合上下文判断，“一起开发”也可能指继续已有项目，不能仅凭该词判定新建。

确定新建意图后直接进入创建流程，不在本 Skill 收集项目名称、ID、路径或规范。新项目尚未登记，不因此转入纳管分支；基础信息确认和重名检查统一由 sdd-product-design 完成。

#### 修改项目

用户要求继续开发、增加功能、调整内容或修复问题时触发，例如“给项目 A 增加导出功能”“继续上次的开发”。修改流程仅处理已纳管项目。

按以下顺序定位目标：用户明确指定的项目 → 当前对话中已确定的项目 → 注册表中的活动项目。对于没有更多上下文、只说“继续上次项目”的新请求，参考注册表中的 `active_project_id`。

根据对应注册记录核对项目身份和实际目录，确定目标项目 ID 与 `active_project_path`。用户指定的项目不能被旧活动项目替代；目标不明确或记录不一致时，只补问缺失信息。确认目标尚未纳管时，转入纳管分支。

#### 删除或重置项目

用户要求清测试数据、重跑阶段、完全移除项目或从头创建时触发。先定位项目；沿用已明确的清理范围，范围不明确时补问，不把“重跑测试”自动理解为删项目。

## 二、根据用户意图进入对应流程

### 创建项目

进入 [sdd-product-design](../sdd-product-design/SKILL.md)，传入 `harness_root`、用户的项目要求和已有的基础信息；允许名称、ID 和 `active_project_path` 尚未确定，不为补齐这些字段停留在本 Skill。

### 修改项目

明确用户希望继续或修改的内容，按 [修改与继续项目](references/modify-project.md) 进入对应阶段。

### 纳管已有项目

已有项目未纳管时，先建议将其纳入 SDD，说明原项目路径并请求用户授权；已有明确授权则沿用。授权后按 [纳管已有项目](references/onboard-project.md) 执行，完成后再继续用户原本的请求。

### 删除或重置项目

按 [删除或重置项目](references/remove-reset-project.md) 确定清理范围、服务处理与登记更新。不为删除一个外部项目先纳管它；只执行用户明确指定的范围。

只读取本次命中的 Skill 或 reference，不预读其他分支。

路由判断在内部完成，不逐级向用户复述“这是项目工作”“即将进入某 Skill”。直接推进命中流程；只有意图仍有歧义时，才简短说明并补问。

每次完成请求后，列出本次新增、修改、删除的文件及准确路径；没有改动时说明“本次未修改文件”。
