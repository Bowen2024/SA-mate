# 后端开发工作流（default）

仅项目明确选择 `default` 且任务引用本件时使用。此处保留默认后端的工程要求；派发、状态和返工由开发循环协议管理。
环境、Python 与 PyCore 用法见 `tech-stack.md`，分层见 `layers.md`，接口规范见 `api-design.md`。

## 当前任务的依据

- 从 `.sdd/tasks.json` 获取派发任务、依赖及 `context_files`，只读其中关联的章节。
- `docs/PRD.md` 中的需求 ID 和 AC 是用户结果与范围的依据；Feature 分组与任务映射在 Plan 生成的 `.sdd/tasks.json` 中，旧项目沿用原引用。
- `docs/tech-spec.md` §二定义接口契约，§三定义数据，§七定义环境、配置及验证方式。
- 不另建功能实施计划或进度文档；所有执行状态由编排器写入 `.sdd/tasks.json`。
- 缺契约、需改变范围或依赖未就绪时，说明受影响 AC 并交回编排器，不自行改 AC 或阻塞无关任务。

## 环境与外部服务

1. 首次需要后端环境时，按 `tech-stack.md` 探测 Python 3.11+、创建项目内虚拟环境并安装依赖；复用已有确认结果。
2. 核对技术方案 §七中本任务的配置项、外部服务、测试权限和已授权调用范围。
3. 把已确认的配置字段落到 `.env.example`，真实配置使用已授权的本地配置文件；不得打印密钥。
4. 实际探测到的解释器、工作目录和验证结果返回编排器；不为记录环境自行改写设计方案。
5. 普通占位配置、SQLite、本地 Mock 不构成统一开工门槛；必要权限缺失只影响依赖它的任务或 AC。
6. 已明确授权的付费调用无需重复确认；未授权的用途、额度或资源交回编排器，不以持有 Key 推定授权。
7. 允许 Mock/fallback 时明确标注验证边界；真实 AC 尚未验证不得报告真实联调通过。

项目虚拟环境内依赖安装、lint、typecheck、单元测试和短时运行检查可在任务范围内执行。
全局安装、系统配置、额外付费资源或长期服务需要已有授权；否则说明具体需求交回编排器。
密钥、日志和外部客户端要求见 `shared/security.md`；报告只保留必要脱敏字段。

## 分层实现

按依赖从下往上实现，保持默认 PyCore/FastAPI 项目的分层：

```text
models/（Pydantic）→ db/models.py（ORM）→ repositories/
  → services/ → api/deps.py → api/routes/
```

- 每层只依赖下层，不得反向依赖；先落实当前任务必需的数据读写，再实现上层能力。
- 数据模型、接口字段和状态必须能追溯到技术方案 §二、§三以及 PRD 中的需求与 AC。
- 任务需要真实用户闭环时，同步对应前端 service / store / page，使 `VITE_USE_MOCK=false` 走真实后端。
- 没有直接前端入口的基础设施任务按其技术检查验收，不强造页面闭环。
- 调整已确认接口、字段或范围前先返回编排器，不在代码中替换产品定义。

## 范围内自验与真实联调

以下技术要求按当前改动适用范围执行；纯文字小改不为满足清单新建测试工程：

- 使用已确认的 Python 指令执行 ruff、mypy；范围为 `backend/src` 和 `backend/tests`，不把 PyCore 依赖包纳入项目质量门禁。
- 运行 pytest 时必须先确认 `pytest-timeout`，命令带 `--timeout`；缺失先在项目虚拟环境补装，失败报告 BLOCKED，不裸跑。
- 涉及启动、数据库或维护脚本时，从 `backend/` 目录执行真实短时验证，启动命令保留 `PYTHONPATH=..`。
- 涉及数据库字段时核对技术方案 §三，并验证实际表、约束与任务要求的持久化结果。
- 外部接口在已有授权范围内验证；核对技术方案 §二的请求与响应，只记录必要脱敏结构。
- 真实业务闭环通过实际页面操作确认请求到达后端、结果返回并可见，不能用 curl 成功代替用户 AC。
- 若真实调用不可执行，保留已完成的局部检查，说明受影响 AC 与原因，不把 Mock 结果写成真实 PASS。
- 自验失败时修复本任务内问题并针对性复验；Tester 独立验证后把结论和证据交回编排器。

## Mock 退出

前端 Mock 服务于被派发的模拟任务，不规定全项目必须先完成全部 Mock 页面。
真实功能接入后：

1. 对应 `frontend/src/services/` 在 `VITE_USE_MOCK=false` 时调用真实后端 API。
2. 可保留开发演示用 Mock 分支，但不作为该功能的真实验收路径。
3. 移除真实路径上的 `[Mock]` 提示和仅适用于模拟模式的文案。
4. Tester 按 AC 验证实际请求与用户结果，不把构建成功当作联调完成。

## 测试库隔离

- `backend/tests/*` 使用独立测试库、临时库或事务回滚夹具，禁止使用运行时业务库做清表测试。
- 不得导入运行时 `engine` / `async_session_maker` 后执行 `drop_all` 或等价清理。
- FastAPI 集成测试通过 `app.dependency_overrides[get_db]` 注入测试库 session；清理只作用于测试库。
- 执行数据库测试后检查真实业务库核心表和必要 seed 数据仍存在，不能出现测试全绿但业务数据被清空。

## 返回结果

返回任务 ID、AC、自验或验收结果、改动路径以及必要复现命令，长证据按需保存到单份任务报告。
示例请求与预期响应以技术方案 §二为准；用户启动步骤沿用 §七中已确认的方式和本集端口约定。
项目运行说明按交付任务维护在项目 `README.md`，不新增独立启动文档或全局进度表；编排器统一记录任务状态和证据引用，并决定后续动作。
