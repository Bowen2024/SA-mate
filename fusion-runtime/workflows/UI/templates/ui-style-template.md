# UI 设计与演示文档模板（本地适配）

生成明确业务项目或授权隔离试验目录中的 `docs/ui-style.md` 时使用，不用当前工作目录猜测项目。本文是模板说明，实例不复制本段的维护说明。先说明设计目标和要素分析所得的判断，再写全局视觉系统、组件与逐页细节，使设计决定能追溯到用户任务和使用约束。

按当前项目规模展开；共用设计写一次，页面只写具体应用或例外。不要机械复制历史项目的功能、数据或全部色板，也不额外生成一套全局与逐页文档。

## 文档头部

- 项目名称、`status: Draft`、适用平台、本轮范围和涉及的界面；说明是业务候选还是隔离试验，不用文件状态代表正式确认。
- 依据的 PRD 需求 / AC，或可定位的场景／材料章节与本轮明确决定；没有 PRD 不伪造编号。记录采用的来源路径、实际版本／摘要及未知来源，不编造工具元数据。
- 展示对象与目的、用户起点与完成结果、目标用户与主要约束；参考与已有设计注明来源，事实、建议和假设分开。
- 设计基准视口及适配范围；根据当前产品选择，不固定所有项目用同一尺寸。
- 已有设计的修改需说明保留与调整的部分；首次设计说明关键选择依据。

## 一、设计目标与风格判断

### 产品类型与体验目标

说明产品类型、核心用户与主任务、信息密度和使用情境。把体验目标落实到设计判断，例如“坐席需要同时处理队列和对话，因此主区突出当前会话，操作区保持可见”。业务范围引用 PRD 或本轮已明确的场景与来源；不为布局增加功能。

### 视觉风格

写选定风格的名称、视觉特征和适用理由，以及需要避免的效果。将信息层级、阅读密度、布局与使用约束转成具体取舍；用户已确认的要求与设计建议分别说明。已有明确方案直接继承，比较过候选时简述取舍，不要求先调用其他设计 Skill。

### 关键 UX 规则

列本项目最重要的几条：主操作层级、状态可感知、错误后的恢复、保留用户输入、长内容或等待时的呈现等。每条都说明对应的页面/组件及可观察表现，避免只写抽象形容词。

### 演示主线与模拟边界

用“操作前状态 → 用户动作 → 可见结果与下一步”串起必要页面，标明前端实际执行、模拟业务处理与未实现部分。模拟等待和结果不作为真实服务或模型效果证据。

说明同一记录跨页变化、重复操作处理、适用的失败与重试、刷新后的状态，以及重置到演示起点的操作。是否采用本地存储按场景决定，采用时说明范围和清理方式，不默认引入后端。

首次／整体换风格时记录代表页面、有效反馈与采用方向；已有风格局部修改直接说明保留和变化，不机械重做风格选择。先明确关键约定再制作，交付前同步实际页面。

## 二、全局视觉系统

### 配色方案

| 名称 | 色值 | 用途 | 适用组件或状态 |
| --- | --- | --- | --- |
| Primary / Secondary / CTA | 填实际值 | 区分主次与动作 | 关联具体组件 |
| Background / Surface / Text / Border | 填实际值 | 背景、表面、文字与边界 | 说明层级 |
| Success / Warning / Error | 按需填写 | 状态反馈 | 同时提供文字或图形提示 |

使用语义名称；只定义项目用到的颜色。页面引用名称，不重新抄一套不同色值。记录必要的文字与背景搭配、焦点和禁用效果。

### 字体与字阶

| 用途 | 字体与回退 | 字号 | 字重 | 行高 / 字距 |
| --- | --- | --- | --- | --- |
| 页面标题、区块标题、正文、辅助信息 | 分别填写 | 带单位 | 实际值 | 实际值 |

说明中文、英文与数字混排；有日志或代码内容时再定义等宽字体。字体不可用时采用已写明的回退。按目标设备说明必要的字号变化。

### 布局、间距与形状

写明内容宽度、分区比例、边距、间距刻度、组件高度、圆角及响应式变化。区分坐席工作台等高密度场景与普通用户页面，不把历史案例的列数强制套给所有页面。

### 层次、阴影与动效

说明背景、内容区、浮层怎样区分；边框、阴影和遮罩如何使用。需要动效时写触发条件、用途、时长与减弱动效方式；不需要时明确保持静态。

| 组件 | 外观与全局值引用 | 主次层级 | 适用状态及表现 |
| --- | --- | --- | --- |
| 填实际组件 | 引用配色、字阶、尺度 | 说明用途 | 默认、禁用、聚焦等 |

按目标设备定义悬停、按下等适用状态；说明加载、空内容、错误和成功的表现。业务触发条件引用 PRD 或本轮明确决定，不在风格文档中另设权限或业务规则。

## 四、界面清单与页面设计

从 PRD 或已明确的演示场景确定本次必要界面；已有 REQ / AC 沿用原 ID，没有时关联来源章节／本轮场景，不伪造需求编号。界面编号与原型锚点保持稳定。页面较多时可先列索引，再按任务只读有关页面。

每个页面按以下小节描述；简单页面可简写，适用内容仍须明确，不能只写尺寸或成功/失败颜色。共用规则引用即可，不为填模板添加业务能力：

### 界面编号与名称

- **依据与目标**：关联的需求 / AC 或来源场景、本页面让用户完成什么；原型路径仅在实际存在时填写。
- **布局结构**：共用外壳与独立页面、导航对应关系、整体分区及信息阅读顺序；标明主要操作位置、可用高度、滚动归属和窄屏变化。互斥页面不同时展示；长内容不得挤压或遮挡输入与操作区。
- **内容呈现**：列表或表格的行列层级、对齐、间距、长文件名或文本的换行/截断方式。按本页任务设计，不能只给“文件选择框与按钮同排”等局部说明。
- **组件清单**：表格列为 `区域 | 组件类型 | 内容/数据 | 交互表现 | 全局风格引用`。
- **状态与操作结果**：按 `操作前状态 → 用户动作 → 可见结果与下一步` 描述关键交互，覆盖适用的空、加载、错误、成功或禁用状态；跨页面有影响时说明同步结果。主次按钮随当前状态组织，不能用弹窗文字代替主流程，不重新定义业务权限。
- **示例数据与文案**：使用符合项目语境的脱敏或虚构展示数据，标明仅供设计演示。列表给足够体现重复项与状态差异的内容，通常至少两条；对话给能体现角色和反馈的完整往返。数据与真实字段对应，显示文案使用业务名称，不把内部枚举直接呈现给用户；技术计数仅在有助判断时显示并说明含义。不创建已明确业务范围之外的功能。
- **页面例外**：只有全局样式无法满足场景时填写，说明覆盖的值、理由和适用范围。

## 五、使用与验收

列出本项目应采用与应避免的具体做法，并检查：

- 每个本次界面均可找到布局、组件、必要状态及示例，且与需求 / AC 或本轮明确场景范围一致。
- 色值、尺寸、状态在表格、正文及页面之间一致；全局值与页面例外没有歧义。
- 主操作、焦点、表单标签和反馈可辨认；长文本、空内容及目标设备的适配方式已说明。
- 有原型时按阶段 B 实际打开、刷新和切换各页面，在约定视口下核对页面互斥、滚动、输入区位置及视觉层级，并操作主流程和关键失败场景；修正后复查。
- 在本节简记实际验证的页面/锚点、视口、操作、结果与未验项。区分源码检查、截图观察与实际浏览器操作，不把文件存在或 DOM 检查当作视觉通过；无法访问时明确未完成项。
- 记录用户实际反馈的范围与版本，不把沉默、草稿或 Agent 自验当作认可；不自行改为 Confirmed。正式用途确认只引用实际可核验记录，缺失时如实说明。仅讨论而无页面时只声明完成文档检查，不能用此代替已要求的可操作演示。

风格文档持续保留，供原型、开发和测试引用。改动只影响相关全局值、页面或组件时，更新对应章节与关联产物，不重写全套设计。


## 演示说明与版本接续

演示目录内的 README 承担实际入口、工作目录、环境与依赖、启动／停止、端口、演示步骤、重置、模拟范围和限制；本设计文档引用实际存在的说明位置，不重复维护另一套启动命令。

验收简记保留实际页面／锚点、场景、视口、操作、结果、时间和所测代码版本／摘要。未验项说明原因；只观察截图就限定在该画面，不宣称已操作流程。代码变化后复查受影响内容，说明更新则保留与所测代码的对应关系。

本轮修改列明保留和变化、来源待同步项、候选／实际保存位置与未完成内容，供下一会话读取。工具未接通时不伪造 read_id、成果集合历史、保存结果或正式确认。源码、素材、模拟数据、说明和适用依赖声明共同构成成果，不把单个 Markdown 当作完整 UI 版本。
